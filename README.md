# BGP Watch — @BGPWatchRobot

Telegram-бот: следит за доступностью серверов по IP двумя сигналами —
**TCP-проба** (принимает ли хост соединение) и **BGP-видимость** префикса
(RIPEstat / RIPE RIS). Пишет при любом изменении статуса. Проверка каждые 15 минут.

Подробности и обоснование решений — в [SPEC.md](SPEC.md).

## Команды

| Команда | Действие |
|---|---|
| `/start` | приветствие |
| `/watch <ip> [порт]` | следить (порт по умолчанию 22) |
| `/unwatch <ip>` | перестать следить |
| `/name <ip\|CIDR> <название>` | личное название подписки; `-` убирает имя |
| `/list` | мои IP + статус |
| `/status <ip>` | проверить сейчас |
| `/help` | справка |

Название видно рядом с IP в списке, статусе и уведомлениях. Оно сохраняется при
повторном `/watch`, относится только к вашему чату и может содержать до 64 символов.
Для IP с несколькими портами `/name` меняет название всех его текущих подписок.

## Локальная разработка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m pytest -q          # тесты
cp .env.example .env                    # вписать BOT_TOKEN
.venv/bin/python -m bgpwatch            # запуск
```

## Деплой (Ubuntu, systemd)

```bash
./deploy/deploy.sh root@SERVER
# затем на сервере:
#   printf 'BOT_TOKEN=XXX\n' > /opt/bgpwatch/.env && chmod 600 /opt/bgpwatch/.env
#   chown bgpwatch:bgpwatch /opt/bgpwatch/.env
#   systemctl enable --now bgpwatch
#   journalctl -u bgpwatch -f
```

Используется **long-polling** — порт/cert/nginx не нужны.

Повторный деплой выбирает Python из фактического `ExecStart` systemd, включая
drop-in с `.venv-security`. Пакеты устанавливаются именно в это окружение;
существующие drop-in сохраняются. Одновременно допускается один деплой.

Перед изменениями скрипт сохраняет код, requirements, выбранный venv и unit в
`/var/backups/bgpwatch/`. Затем останавливает работавший сервис, устанавливает
релиз и проверяет новый процесс: подключение к Telegram и первый цикл мониторинга
должны появиться в журнале в пределах проверки на 180 секунд; последние 5 секунд
процесс должен оставаться стабильным. При ошибке установки или запуска
восстанавливаются файлы и зависимости, прежний сервис запускается и проходит ту же проверку. Неуспешный
деплой возвращает ненулевой код даже после успешного отката.

`.env`, SQLite и сохранённый Telegram IP не копируются и не заменяются. Резервные
копии остаются на сервере для отката; временный каталог загрузки удаляется.
Если сервис до деплоя был остановлен или ещё не существовал, он автоматически
не запускается — сначала настройте `.env` и выполните команду запуска выше.

## CI

GitHub Actions запускает тесты, проверку зависимостей и синтаксиса deploy-скрипта
на Python 3.11 и 3.14 при push, pull request и ручном запуске. Отдельное окружение
`pip-audit` проверяет точные runtime-версии из `requirements.txt`. Workflow не
содержит production-деплоя и не требует секретов.

## Стек

Python 3.11+, единственная зависимость — `httpx` (чистый Python, без компиляции).
TG-клиент минимальный (`bgpwatch/telegram.py`), без aiogram/aiohttp.

## Безопасность

- `BOT_TOKEN` только в `.env` (chmod 600), не в git, не в логах.
- При утечке токена — `/revoke` в @BotFather.
- Бот публичный: любой пользователь может следить за любым IP.
